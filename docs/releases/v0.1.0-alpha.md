**First alpha, a debug snapshot.** Redox OS boots from the SD card on a
Raspberry Pi 3 Model B+, with a USB keyboard and HDMI. Expect rough edges:
about every third command fails (see below). This release is for people who
want to try it or help track down that bug, not for daily use.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## What works

- Boots from the SD card to a login prompt on HDMI, in about half a minute.
- **USB keyboard** (US layout) on the console. `Super` (Windows/Raspberry
  key) + `F1` shows the boot log, `Super` + `F2` the login console.
- **All four CPU cores.**
- **SD card**: root filesystem on the card, reading and writing (at a reduced
  clock, so not fast).
- **Ethernet** (onboard LAN7515): DHCP address, TCP.
- `reboot` (as root).
- Shell `ion`, coreutils (`ls`, `cat`, …), `ps`, `free`, `df`, the editor
  `kibi`, `diff`/`cmp`.

## Known issues

- **Programs fail at random.** About every third command ends at once with
  no output and exit code 1; running it again usually works. It happens in
  QEMU too: a bug in Redox for aarch64, under investigation in
  [docs/debugging-random-crashes.md](https://github.com/redox-rpi/redox-rpi/blob/main/docs/debugging-random-crashes.md).
  Help welcome!
- Many prebuilt programs (bash, nano, vim, curl, wget, …) do not start; they
  are not in the image.
- No `poweroff`: use `reboot`, then pull the power.
- No clock: files are dated 1970.
- Only the Pi 3 Model B+. Pi 3 Model B, Zero 2 W and Pi 4 are not supported
  yet. No Wi-Fi, Bluetooth, audio or USB storage.
- Harmless boot messages about PCI (`pcid … panicked`) and audio.

Full list: [docs/known-issues.md](https://github.com/redox-rpi/redox-rpi/blob/main/docs/known-issues.md).

## Install

1. Download `redox-rpi-v0.1.0-alpha-pi3bplus.img.xz` (about 21 MB, 1.1 GB
   unpacked) and check it against `SHA256SUMS`.
2. Write it to a microSD card of at least 2 GB, with Raspberry Pi Imager
   ("Use custom"), balenaEtcher, SwiftFlash, or on Linux/macOS:

   ```sh
   xz -dc redox-rpi-v0.1.0-alpha-pi3bplus.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Raspberry Pi 3 Model B+, connect HDMI, a USB keyboard
   and, if you like, Ethernet; power on.
4. Log in as `root` with password `password` (or as `user` without password).

The card holds a FAT partition with the Raspberry Pi firmware, U-Boot and the
Redox bootloader, and a 990 MB RedoxFS partition with the system. A
`.uuid` file on the FAT partition identifies the image for flashing tools.

## Built from

Redox upstream (kernel `6cfaba5`, base `eddcaa2`, relibc `841d29c`, the rest
from Redox' prebuilt aarch64 packages of 2026-10-26) with this repository's
patches: SMP and watchdog reset for the Pi 3 (kernel), USB host driver
`dwc2d` with hub, keyboard and LAN78xx Ethernet support, SD card driver
fixes (base), and a `fork()` fix plus a loader workaround (relibc). Build it
yourself with `scripts/build-image.sh --sdcard` and `scripts/make-sdcard.sh
--local`; see the repository README.

## For developers

To help with the bugs, boot the Pi over the network from your own build
server instead of flashing a card after every build:
[docs/netboot.md](https://github.com/redox-rpi/redox-rpi/blob/main/docs/netboot.md).
That image also has a remote shell for scripted tests; there are no prebuilt
files for it, you build them yourself.
