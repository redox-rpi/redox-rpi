**Status: release candidate, experimental (alpha). Not for daily use.**

v0.4.0-rc1 is the first candidate for v0.4.0 of Redox OS on the Raspberry
Pi 3 Model B+ and Zero 2 W ([checklist](v0.4.0-checklist.md),
[#253](https://github.com/redox-rpi/redox-rpi/issues/253)). v0.3.0 made the
system dependable; v0.4.0 makes the SD card fast for small writes, gives the
Pi sound from its headphone jack (beta), and lets the network use every
adapter at once.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.3.0

- **Sound from the headphone jack (beta)**
  ([#250](https://github.com/redox-rpi/redox-rpi/issues/250)). A new
  driver, `bcm2835-pwmaudiod`, plays sound through the Pi 3B+'s 3.5 mm jack
  with DMA, and the Redox sound service `audiod` runs again. `tone` makes
  test sound: `tone -s 3 > /scheme/audio`. Limits of the beta: about
  11 bits, one fixed format (44.1 kHz, 16-bit stereo), the output keeps
  running after the sound ends, a faint hiss when idle. The listening test
  passed (#280).
- **Small writes to the SD card are fast**
  ([#16](https://github.com/redox-rpi/redox-rpi/issues/16)). The
  filesystem collects small writes and writes them together: copying 1 MiB
  in 4 KiB blocks takes 0.5 s instead of 12.7 s. Collected data is written
  at the latest 2 s after it came.
- **Every network adapter at once**
  ([#53](https://github.com/redox-rpi/redox-rpi/issues/53)). The network
  stack uses the onboard Ethernet and USB Ethernet adapters together, and
  the DHCP client gets an address for each.
- **Programs keep their registers across signals**
  ([#127](https://github.com/redox-rpi/redox-rpi/issues/127)). Returning
  from a signal handler no longer overwrites the x18 register.
- **Long downloads no longer stall**
  ([#157](https://github.com/redox-rpi/redox-rpi/issues/157)). The kernel's
  scheduler can no longer lose a thread that is ready to run, and a write
  into a pipe waits until all its bytes are in, so `dd` into a pipe keeps
  its data ([#158](https://github.com/redox-rpi/redox-rpi/issues/158)).
- **IPv4 multicast** ([#27](https://github.com/redox-rpi/redox-rpi/issues/27)),
  also through the Pi 3B+'s LAN7800 adapter, for mDNS and similar
  protocols.
- **USB mice and tablets** are seen by the USB driver and reported as input
  events ([#48](https://github.com/redox-rpi/redox-rpi/issues/48)), ready for
  a desktop.
- **Fixes:**
  - The network stack frees a closed TCP connection
    ([#88](https://github.com/redox-rpi/redox-rpi/issues/88)).
  - The bootloader skips a damaged RedoxFS partition instead of stopping
    ([#232](https://github.com/redox-rpi/redox-rpi/issues/232)).
  - The dynamic loader reads a program from disk only once
    ([#240](https://github.com/redox-rpi/redox-rpi/issues/240)).
  - `clock_settime` and `settimeofday` work, so `timesync -s` can set the
    clock by hand ([#51](https://github.com/redox-rpi/redox-rpi/issues/51)).
- **The CPU clock can be set at boot** in `/etc/rpi-firmware/governor`
  (`ondemand`, `performance`, `powersave` or a fixed rate,
  [#23](https://github.com/redox-rpi/redox-rpi/issues/23)).
- **`socdump`** prints the Pi's clock, PLL and GPIO registers, read-only
  ([#224](https://github.com/redox-rpi/redox-rpi/issues/224)).

All issues of this release:
[milestone v0.4.0](https://github.com/redox-rpi/redox-rpi/milestone/3?closed=1).

## Not in this candidate

These are experiments: they are on `main` but not in the release image.
Build them with `scripts/build-image.sh --experiment <name>`:

- SSH server (`sshd`, [#45](https://github.com/redox-rpi/redox-rpi/issues/45)),
  IPv6 with SLAAC (`ipv6`), ping replies (`icmp-echo`);
- time zones with summer time (`timezone`,
  [#46](https://github.com/redox-rpi/redox-rpi/issues/46));
- our package repository, packages that survive a reset (`pkg-repo`,
  `pkg-persist`, `pkg-hold`, [#44](https://github.com/redox-rpi/redox-rpi/issues/44));
- first-boot welcome app (`welcome`), faster boot (`boot-time`,
  `dwc2d-boottime`, [#47](https://github.com/redox-rpi/redox-rpi/issues/47));
- power saving (`eth-speed`, `clock-states`), USB controller restart
  (`dwc2d-restart`, [#151](https://github.com/redox-rpi/redox-rpi/issues/151));
- booting straight from the Pi firmware without U-Boot
  ([#15](https://github.com/redox-rpi/redox-rpi/issues/15)).

## Known issues

- **Audio is a beta:** see the limits above. The boot click is not checked
  yet.
- **Ctrl-C can be lost while a program starts**
  ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)).
- **Signals sent to a single thread can get stuck**
  ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)).
- **The Pi can hang during a long write to the SD card while it
  downloads** ([#151](https://github.com/redox-rpi/redox-rpi/issues/151));
  QEMU doesn't show it.
- `ifconfig` shows no MAC address, and there is no `ip` command.
- No Wi-Fi, Bluetooth, USB storage or `poweroff`. No desktop in the release
  image.
- Many prebuilt programs (bash, nano, vim, curl, …) are not in the image
  ([#40](https://github.com/redox-rpi/redox-rpi/issues/40)).

## Install

1. Download `redox-rpi-v0.4.0-rc1.img.xz` from
   `http://homenodellm:8080/sdcard/` and check it against its `.sha256`.
   With SwiftFlash: `swiftflash source add redox
   http://homenodellm:8080/sdcard/`, then `sudo swiftflash redox:` and
   pick family `redox-rpi`, version `v0.4.0-rc1`.
2. Write it to a microSD card of at least 2 GB (Raspberry Pi Imager "Use
   custom", balenaEtcher, SwiftFlash or `dd`). Everything on the card is
   erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on. For sound, headphones in the
   3.5 mm jack (Pi 3B+).
4. Log in as `root` with password `password`, or as `user` without a
   password.
