**Status: experimental (alpha). Boots on the Pi 3B+ and Zero 2 W, not for
daily use.**

Redox OS on the Raspberry Pi 3 Model B+ and Zero 2 W. v0.2.0 added
hardware; v0.3.0 makes it dependable. Programs no longer crash at start, the
CPU runs at full speed, the SD card has a faster driver, USB and the
network start reliably, and long runs no longer run out of memory.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.2.0

- **Programs start reliably.** Two bugs made programs fail at start:
  - The kernel lost a syscall's result when a signal arrived during the
    syscall ([#12](https://github.com/redox-rpi/redox-rpi/issues/12)).
    Because of it `ps` printed straight to the terminal and `reboot`
    failed; both work now.
  - The C library's signal handling used a CPU register (x18) that
    programs were free to use too
    ([#1](https://github.com/redox-rpi/redox-rpi/issues/1)), so programs
    died in the dynamic loader.

  On a real Pi 3B+ at full speed, 0 of 1000 program starts failed with
  this build (test 113). Before the fixes, 276 of 5100 failed.
- **Full CPU speed.** The CPU runs at 1400 MHz instead of 600 MHz
  ([#20](https://github.com/redox-rpi/redox-rpi/issues/20)), so programs
  start about twice as fast. Redox warns on the console when the Pi is
  short of power or too hot.
- **Faster SD card driver**
  ([#6](https://github.com/redox-rpi/redox-rpi/issues/6)). A new driver for
  the Pi's sdhost controller is the default. It writes about 7.5 MB/s,
  roughly 2.5 times faster than the old driver. In test 30, three stress
  runs on a 15 GB card each wrote 256 MiB and 1000 small files, and the Pi
  was restarted in between: every file was still there and unchanged
  afterwards.
- **No more memory loss in the kernel**
  ([#31](https://github.com/redox-rpi/redox-rpi/issues/31)). A program
  thread that ended itself left about 75 KB of kernel memory behind, so
  long runs ran out of memory. In test 30 the memory in use stayed at
  120 MB over all three stress runs.
- **USB starts reliably.** The USB driver no longer stops when a device
  sends a short answer while it is being set up; it asks again (Pi test
  105: 5 of 5 boots with network). Before, 1 of 2 boots in test 98 had no
  network.
- **The network no longer drops minutes after boot**
  ([#92](https://github.com/redox-rpi/redox-rpi/issues/92)). Older builds
  could lose the network while the serial console kept working; the newer
  kernel and USB network drivers in this release keep it.
- **USB without a busy CPU core.** The USB driver waits for interrupts
  instead of polling, which frees a whole CPU core. The driver for
  RTL8152/RTL8153 USB Ethernet adapters is now part of every image.
- **Serial console keeps fast input**
  ([#28](https://github.com/redox-rpi/redox-rpi/issues/28),
  [#32](https://github.com/redox-rpi/redox-rpi/issues/32)). Pasted text
  and fast typing no longer lose characters or crash the login prompt.
- **Clean boot**
  ([#18](https://github.com/redox-rpi/redox-rpi/issues/18)). No more error
  messages from the PCI and audio services at boot, since the Pi has
  neither (test 33).
- The release name is shown above the login prompt, next to the build ID.

All issues of this release:
[milestone v0.3.0](https://github.com/redox-rpi/redox-rpi/milestone/1?closed=1).

## What works

- Boots from the SD card to a login prompt on HDMI.
- USB keyboard (US layout). `Super` + `F1` shows the boot log, `Super` +
  `F2` the login console.
- All four CPU cores, at 1400 MHz.
- SD card: root filesystem, read and write.
- Onboard Ethernet on the Pi 3B+: DHCP and TCP.
- Ethernet over USB with RTL8152 and RTL8153 adapters, also on the Zero 2 W.
- Clock from the network (`pool.ntp.org`) and from the last saved time.
- Firmware information under `/scheme/rpi-firmware`.
- `reboot`.

## Known issues

- **USB devices must be plugged in before you power on**
  ([#17](https://github.com/redox-rpi/redox-rpi/issues/17)). A device
  plugged in later is not detected, and a network cable plugged in after
  boot is not picked up. USB hotplug comes in v0.4.0.
- **Ctrl-C can be lost while a program starts**
  ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)). If you press
  Ctrl-C right after starting a program, it may keep running.
- **Signals sent to a single thread can get stuck**
  ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)). Signals to a
  whole program work, but a signal aimed at one thread of a program may
  arrive only once and then stay blocked. Programs that rely on this can
  hang. A fix is being tested.
- **A few program starts may still fail**
  ([#1](https://github.com/redox-rpi/redox-rpi/issues/1)), rarely, at full
  speed. A more complete fix passed on the Pi (test 36, 0 of 1000) and is
  planned for the next release.
- **The clock may stay unset if the network comes up late**
  ([#22](https://github.com/redox-rpi/redox-rpi/issues/22)). If no time
  server answers at boot, Redox does not try again. Restart with the cable
  plugged in. A fix passed on the Pi (test 41).
- Small writes to the SD card are slow: the filesystem writes about 36
  times the data ([#16](https://github.com/redox-rpi/redox-rpi/issues/16),
  planned for v0.4.0).
- On the Zero 2 W the new SD card driver is not tested yet (test 24).
- No Wi-Fi, Bluetooth, audio, USB storage or `poweroff`.
- Many prebuilt programs (bash, nano, vim, curl, …) are not in the image
  yet. They are planned for a later release.

## Install

1. Download `redox-rpi-v0.3.0-pi3bplus.img.xz` and check it against
   `SHA256SUMS`.
2. Write it to a microSD card of at least 2 GB. Use Raspberry Pi Imager
   ("Use custom"), balenaEtcher or SwiftFlash, or on Linux and macOS:

   ```sh
   xz -dc redox-rpi-v0.3.0-pi3bplus.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on.
4. Log in as `root` with password `password`, or as `user` without a
   password.
