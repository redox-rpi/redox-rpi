**Status: experimental (alpha). Boots on the Pi 3B+ and Zero 2 W, not for
daily use.**

Redox OS on the Raspberry Pi 3 Model B+ and Zero 2 W. v0.2.0 added
hardware; v0.3.0 makes it dependable. Programs no longer crash at start, the
SD card has a faster driver, USB devices can be plugged in at any time, the
CPU clock follows the load, and long runs no longer run out of memory. It
also brings the first drivers for the Pi's pin header: GPIO, I2C and SPI.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.2.0

- **Programs start reliably.** Two bugs made programs fail at start:
  - The kernel lost a syscall's result when a signal arrived during the
    syscall ([#12](https://github.com/redox-rpi/redox-rpi/issues/12)).
    Because of it `ps` printed straight to the terminal and `reboot`
    failed; both work now.
  - The C library's signal handling used a CPU register (x18) that
    programs were free to use too
    ([#1](https://github.com/redox-rpi/redox-rpi/issues/1)), so programs
    died in the dynamic loader.

  On a real Pi 3B+ at full speed, 0 of 3000 program starts failed (test
  149), and 0 of 5000 in QEMU. Before the fixes, 276 of 5100 failed.
- **USB devices can be plugged in at any time**
  ([#17](https://github.com/redox-rpi/redox-rpi/issues/17)). The USB
  driver looks for new and removed devices once a second. A keyboard or a
  network adapter plugged in after boot works. With several network
  adapters, the one with a link is used, and the Pi keeps its address when
  it moves to another one. The DHCP client keeps trying, so a cable plugged
  in later gets an address.
- **USB starts reliably.** The USB driver no longer stops when a device
  sends a short answer while it is being set up; it asks again (test 105:
  5 of 5 boots with network).
- **The CPU clock follows the load**
  ([#20](https://github.com/redox-rpi/redox-rpi/issues/20),
  [#23](https://github.com/redox-rpi/redox-rpi/issues/23)). The CPU runs at
  up to 1400 MHz instead of a fixed 600 MHz, so programs start about twice
  as fast. It goes up to 1400 MHz under load and back to 600 MHz when idle.
  `/scheme/rpi-firmware/governor` shows the load and lets you fix the clock
  (`performance`, `powersave`). Redox warns on the console when the Pi is
  short of power or too hot.
- **Faster SD card driver**
  ([#6](https://github.com/redox-rpi/redox-rpi/issues/6)). A new driver for
  the Pi's sdhost controller is the default. It writes about 7.5 MB/s,
  roughly 2.5 times faster than the old driver. In test 30, three stress
  runs each wrote 256 MiB and 1000 small files with restarts in between:
  every file was still there and unchanged.
- **No more memory loss in the kernel**
  ([#31](https://github.com/redox-rpi/redox-rpi/issues/31)). A thread that
  ended itself left about 75 KB of kernel memory behind, so long runs ran
  out of memory. Memory in use now stays the same over long stress runs.
- **The network no longer drops minutes after boot**
  ([#92](https://github.com/redox-rpi/redox-rpi/issues/92)). Older builds
  could lose the network while the serial console kept working; the nightly
  image from current main keeps it (test 119: over 4 hours).
- **GPIO, I2C and SPI** ([#38](https://github.com/redox-rpi/redox-rpi/issues/38),
  [#39](https://github.com/redox-rpi/redox-rpi/issues/39),
  [#42](https://github.com/redox-rpi/redox-rpi/issues/42)), first versions,
  Pi 3B+ (test 99):
  - `/scheme/gpio`: each pin's mode, value and pull. Pins used by the
    serial console and the SD card are refused.
  - `/scheme/i2c` on bus 1 (pins 3 and 5), with the `i2c` tool (`detect`,
    `get`, `set`, `dump`).
  - `/scheme/spi` on SPI0, with the `spi` tool.
  - The red power LED, under `/scheme/rpi-firmware`.
- **Clock set even when the network comes late**
  ([#22](https://github.com/redox-rpi/redox-rpi/issues/22)). `timesync`
  waits for the network and tries again instead of giving up (test 41).
- **USB without a busy CPU core.** The USB driver waits for interrupts
  instead of polling, which frees a whole CPU core. RTL8152/RTL8153 USB
  Ethernet adapters work out of the box.
- **Serial console keeps fast input**
  ([#28](https://github.com/redox-rpi/redox-rpi/issues/28),
  [#32](https://github.com/redox-rpi/redox-rpi/issues/32)). Pasted text and
  fast typing no longer lose characters or crash the login prompt.
- **Clean boot** ([#18](https://github.com/redox-rpi/redox-rpi/issues/18)).
  No more errors from the PCI and audio services the Pi does not have.
- `ls /scheme/netcfg/ifaces` and the other network settings directories
  can be listed ([#105](https://github.com/redox-rpi/redox-rpi/issues/105)).
- The release name is shown above the login prompt, next to the build ID.
- **New user documentation:**
  [getting started](https://github.com/redox-rpi/redox-rpi/blob/v0.3.0/docs/getting-started.md),
  a [user guide](https://github.com/redox-rpi/redox-rpi/blob/v0.3.0/docs/user-guide.md),
  time and smart home.

## What works

- Boots from the SD card to a login prompt on HDMI.
- USB keyboard (US layout), also plugged in after boot. `Super` + `F1`
  shows the boot log, `Super` + `F2` the login console.
- All four CPU cores, 600 to 1400 MHz.
- SD card: root filesystem, read and write.
- Onboard Ethernet on the Pi 3B+: DHCP and TCP.
- Ethernet over USB with RTL8152 and RTL8153 adapters, also on the Zero 2 W.
- Clock from the network (`pool.ntp.org`) and from the last saved time.
- GPIO, I2C bus 1 and SPI0 on the Pi 3B+.
- Firmware information under `/scheme/rpi-firmware`.
- `reboot`.

## Known issues

- **Ctrl-C can be lost while a program starts**
  ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)). If you press
  Ctrl-C right after starting a program, it may keep running.
- **Signals sent to a single thread can get stuck**
  ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)). Signals to a
  whole program work, but a signal aimed at one thread may arrive only once
  and then stay blocked. Programs that rely on this can hang.
- **A program whose last thread ends with `pthread_exit` is reported as
  killed** ([#108](https://github.com/redox-rpi/redox-rpi/issues/108)): its
  exit status is SIGKILL instead of 0. The fix (experiment
  `self-exit-status`, test 133) is planned for the next release.
- Small writes to the SD card are slow: the filesystem writes about 36
  times the data ([#16](https://github.com/redox-rpi/redox-rpi/issues/16),
  planned for v0.4.0).
- On the Zero 2 W the new SD card driver and USB hotplug are not tested
  yet.
- No Wi-Fi, Bluetooth, audio, USB storage or `poweroff`.
- Many prebuilt programs (bash, nano, vim, curl, …) are not in the image.
  They run with the experiments `prebuilt-programs` and `sigreturn-svc`
  ([#40](https://github.com/redox-rpi/redox-rpi/issues/40)) and are planned
  for a later release.

## Install

1. Download `redox-rpi-v0.3.0-pi3bplus.img.xz` and check it against
   `SHA256SUMS`.
2. Write it to a microSD card of at least 2 GB. Use Raspberry Pi Imager
   ("Use custom"), balenaEtcher or SwiftFlash, or on Linux and macOS:

   ```sh
   xz -dc redox-rpi-v0.3.0-pi3bplus.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on.
4. Log in as `root` with password `password`, or as `user` without a
   password.

The [getting started guide](https://github.com/redox-rpi/redox-rpi/blob/v0.3.0/docs/getting-started.md)
explains each step.
