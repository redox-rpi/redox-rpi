**Release candidate, for testing. Not for daily use.**

The third test build for v0.3.0 of Redox OS on the Raspberry Pi 3 Model
B+ and Zero 2 W. If nothing serious turns up, the same commit becomes
v0.3.0. Please try it and report what breaks
([issues](https://github.com/redox-rpi/redox-rpi/issues)).

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## What changed since v0.2.0

- **Programs start much more reliably.** The kernel no longer loses a
  syscall's result when a signal arrives
  ([#12](https://github.com/redox-rpi/redox-rpi/issues/12)), and the C
  library no longer shares a CPU register with the program
  ([#1](https://github.com/redox-rpi/redox-rpi/issues/1)). `ps` and
  `reboot` work again. On a real Pi 3B+ at full speed, 0 of 1000 program
  starts failed with this build (test 113), as with rc2 (test 102).
- **Full CPU speed:** 1400 MHz instead of 600 MHz
  ([#20](https://github.com/redox-rpi/redox-rpi/issues/20)). Redox warns
  on the console when the Pi is short of power or too hot.
- **Faster SD card driver**
  ([#6](https://github.com/redox-rpi/redox-rpi/issues/6)): about 7.5 MB/s,
  roughly 2.5 times the old driver. In test 30 the Pi was restarted between
  stress runs, and no file was lost or changed.
- **No more memory loss in the kernel**
  ([#31](https://github.com/redox-rpi/redox-rpi/issues/31)): long runs no
  longer run out of memory. Memory in use stayed at 120 MB over three
  stress runs.
- **USB starts reliably:** the USB driver no longer stops when a device
  sends a short answer while it is being set up; it asks again (PR #84,
  Pi test 105: 5 of 5 boots). Without the fix, 1 of 2 boots in test 98 had
  no network.
- **The network no longer drops minutes after boot**
  ([#92](https://github.com/redox-rpi/redox-rpi/issues/92)). Older builds
  could lose the network while the serial console kept working; the newer
  kernel and USB network drivers in this release keep it.
- **USB without a busy CPU core:** the USB driver waits for interrupts
  instead of polling. RTL8152/RTL8153 USB Ethernet adapters work out of
  the box.
- **Serial console keeps fast input**
  ([#28](https://github.com/redox-rpi/redox-rpi/issues/28),
  [#32](https://github.com/redox-rpi/redox-rpi/issues/32)): pasted text no
  longer loses characters or crashes the login prompt.
- **Quieter boot** ([#18](https://github.com/redox-rpi/redox-rpi/issues/18)):
  no more errors from PCI and audio services the Pi does not have.
- The release name is shown above the login prompt, next to the build ID.

## Known problems

- **Ctrl-C can be lost while a program starts**
  ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)). If you press
  Ctrl-C right after starting a program, it may keep running. A fix is in
  testing (test 80); with it, Ctrl-C works over the network shell, but on
  the serial console it still arrives only when the program ends.
- **USB devices must be plugged in before you power on**
  ([#17](https://github.com/redox-rpi/redox-rpi/issues/17)). A device
  plugged in later is not detected, and a network cable plugged in after
  boot is not picked up. USB hotplug comes in v0.4.0.
- **Signals sent to a single thread can get stuck**
  ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)). Programs that
  rely on them can hang.
- **A few program starts may still fail**
  ([#1](https://github.com/redox-rpi/redox-rpi/issues/1)), rarely, at full
  speed. The complete fix passed on the Pi (test 36, 0 of 1000) and waits
  for its merge (PR #61).
- Small writes to the SD card are slow
  ([#16](https://github.com/redox-rpi/redox-rpi/issues/16), planned for
  v0.4.0).
- If the network comes up late, the clock may not be set from the network
  ([#22](https://github.com/redox-rpi/redox-rpi/issues/22)); restart with
  the cable plugged in. The fix is PR #59.
- No Wi-Fi, Bluetooth, audio, USB storage or `poweroff`. Many prebuilt
  programs (bash, nano, vim, …) are not in the image yet.
- On the Zero 2 W the new SD driver is not tested yet (test 24).

## Install

1. Download `redox-rpi-v0.3.0-rc3.img.xz` and check it against
   `SHA256SUMS`, from
   [the release page](https://github.com/redox-rpi/redox-rpi/releases/tag/v0.3.0-rc3)
   (until it is published: `http://homenodellm:8080/sdcard/` on the test
   network, with `redox-rpi-v0.3.0-rc3.img.xz.sha256`).
2. Write it to a microSD card of at least 2 GB with Raspberry Pi Imager
   ("Use custom"), balenaEtcher or SwiftFlash, or:

   ```sh
   xz -dc redox-rpi-v0.3.0-rc3.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W, connect HDMI, a USB
   keyboard and Ethernet, then power on.
4. Log in as `root` with password `password`, or as `user` without a
   password.
