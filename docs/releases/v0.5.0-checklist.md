### Known issues so far

From v0.4.0, still true: Ctrl-C can be lost while a program starts (#55);
`pthread_exit` reported as SIGKILL (#108); signals to one thread can get
stuck (#4); fast paste into the serial console can lose a character (#28);
one screen resolution, no hotplug; Orbital cannot be stopped; the Zero 2 W
network-boot image has no desktop. The SD-write hang of #151: the download
stall is fixed by #373 (rows 343–345); whether #151 is closed is for its
owner. DNS (#290) and the missing HTTP client are fixed (#358, #368).

New for v0.5.0:

- **Network lost minutes after boot ([#92](https://github.com/redox-rpi/redox-rpi/issues/92))**
  and **login without network ([#217](https://github.com/redox-rpi/redox-rpi/issues/217))**,
  missing from v0.4.0's list (Quality). Both rare: 17 and 10 Pi rows name
  them; the last sighting was row 316 (one boot of several), and rows 319,
  321 and 323 saw none. #344 and #373 (merged) remove the stall mechanisms
  found so far. The nightly records of #369 give a measured rate from
  2026-11-13 on; the notes give what they show by Saturday.
- Sopwith's window is cut off on small screens (656x416 without a monitor).
- First-boot setup (`welcome`, #24) is not in the release options: the
  card logs in as `root` / `password` (T-SEC-1 gap).
- curl prints `TODO: setsockopt(...)` lines per connection (relibc); wget
  is not in the image, it corrupts HTTP downloads (#365).
- The Zero 2 W image has no curl (no room); `pkg install curl` there.
