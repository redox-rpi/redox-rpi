### Known issues so far

From v0.4.0, still true unless a fix above is merged: Ctrl-C can be lost
while a program starts (#55); `pthread_exit` reported as SIGKILL (#108);
signals to one thread can get stuck (#4); the Pi can hang during a long
SD write while downloading (#151); fast paste into the serial console can
lose a character (#28); DNS ignores the DHCP name server (#290, unless
#358); no HTTP client (unless #368); one screen resolution, no hotplug;
Orbital cannot be stopped; the Zero 2 W network-boot image has no desktop.

New for v0.5.0:

- **Network lost minutes after boot ([#92](https://github.com/redox-rpi/redox-rpi/issues/92))**
  and **login without network ([#217](https://github.com/redox-rpi/redox-rpi/issues/217))**,
  missing from v0.4.0's list (Quality). Both rare: 17 and 10 Pi rows name
  them; the last sighting was row 316 (one boot of several), and rows 319,
  321 and 323 saw none. PR #344 (merged) removes the stall mechanism found
  in row 316. A measured rate comes from the nightly records of PR #369
  once it runs; until then the notes say "rare, seen in single boots".
- Sopwith's window is cut off on small screens (656x416 without a monitor).
- First-boot setup (`welcome`, #24) is not in the release options: the
  card logs in as `root` / `password` (T-SEC-1 gap).
- wget is not in the image: it corrupts HTTP downloads (#365).
