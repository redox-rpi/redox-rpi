# v0.6.0 readiness check

Quality, 2026-11-17 (main 407272f8), for the cut-off on Friday 2026-11-20
and `v0.6.0-rc1` on Saturday. This page lists what proves each open v0.6.0
item and what is still missing. The steps themselves are in the
[checklist](v0.6.0-checklist.md), the rows are in
[pi-tests queue.md](https://github.com/redox-rpi/pi-tests/blob/main/queue.md),
and the reports are in
[reports/](https://github.com/redox-rpi/pi-tests/tree/main/reports).
"Dev build" means a row on a build before rc1. Under the
[RMP](../process/rmp.md), the release still needs the criterion on the
candidate, or the maintainer has to accept it explicitly.

## Summary

- **Ready for rc1:** #324 (direct card) and #492 (adapter check), if the
  planned rc1 rows run (449, 450, 458).
- **Update 2026-11-22:** rows 450, 458 and 449 have run, see the table
  below. Open: REQ-NET-1 criterion 5 (was 3; 100/100 boots, proposed;
  #576, fix not in rc1), REQ-NET-4 criterion 2 (#88).
- **Update 2026-11-22, requirements reworded** (user's decision): REQ-NET-1
  (#491, approved) asks for DHCP within 60 s after link-up on every supported
  adapter; REQ-NET-2 (#492, proposed) is only the adapter list. Tests 571
  (3B+, rc2) and 574 (Zero, rc3) meet NET-1 criterion 1 and NET-2, so the
  RTL8153-hub gap is closed. **New and untested:** NET-1 criterion 2 (one log
  line after 60 s without an answer, then quiet retries) and criterion 3
  (replugging restarts the count). They need a test on a candidate, or the
  maintainer accepts them as open for v0.6.0. Trace:
  [trace-v0.6.0.md](../requirements/trace-v0.6.0.md).
- **Waiting for a merge by the maintainer:** #418/#484 (PR #526, which has
  a pass on a dev build); `merge-next` PRs #446 and #458 conflict with main
  right now.
- **Gaps, now covered by rc1 row 474** (added after this check):
  1. No rc1 run of the standard release tests (row 414 on v0.5.0): row 474
     part A. REQ-FW-3 criterion 1 and REQ-CON-2 criteria 1 and 2 get their
     test on the v0.6.0 candidate there.
  2. REQ-FW-3 criterion 3 (a synced file survives `poweroff`): row 474
     part C, only if #526 is in.
- **REQ-CON-2 (#481, #28), 2026-11-17:** the lost lines were the old
  `serial-input-test.sh` waiting only 30 s, not the UART (Tests 490, 491:
  0 lost, `rx_overruns` 0, stable image 100 of 100). PR #547 gives the
  script a 120 s wait. Row 474 step 5 must use that script (main with
  #547, or the Test 491 copy), or a slow run fails rc1 with nothing lost.
- **Risk for the rc1 image:** draft PRs #532 (Ri-li), #534 (Tux Typing,
  relibc 0020) and #535 add games to `orbital-apps`, which is in the rc1
  release options. With Ri-li the 256 MiB filesystem is 99 % full, and
  Tux Typing needs 384 MiB. The direct card runs that filesystem from RAM
  (Zero 2 W: 512 MB). They need their own experiment outside the release
  options, or a merge after rc1 (review comments on the PRs).
- **Will probably miss the cut-off:** #450 (PR #527 is a draft, and the
  several-devices part needs a person).
