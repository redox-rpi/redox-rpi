**Status: release candidate, experimental (alpha). Not for daily use.**

**Draft:** the candidate checks, QEMU and the automated Pi test (row 414,
Pi 3B+) pass. The person test on the SD card is still open. No tag without the maintainer's OK on
the exact commit.

v0.5.0-rc1 is the first candidate for v0.5.0 of Redox OS on the Raspberry
Pi 3 Model B+ and Zero 2 W ([checklist](v0.5.0-checklist.md), milestone
[v0.5.0](https://github.com/redox-rpi/redox-rpi/milestone/8)). v0.4.0 gave
the Pi a desktop and sound; v0.5.0 puts a game on the desktop, a C
compiler on the Pi and a startup sound in the speaker, and makes the
network more dependable.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.4.0

- **A game on the desktop** ([PR #298](https://github.com/redox-rpi/redox-rpi/pull/298)).
  The desktop's text editor, whose save dialog did not work (#33), is
  replaced by Sopwith, a small biplane game (arrows, space fires, `b`
  drops bombs). `desktop` starts the desktop without a question. It first
  shows how to get back (Super+F2 console, Super+F3 desktop, Super+T
  terminal) and the desktop's limits, also in a window after the login.
- **A C compiler on the Pi (beta)** ([#293](https://github.com/redox-rpi/redox-rpi/issues/293)).
  TinyCC (`tcc`) compiles C on the Pi itself:
  - `tcc -o hello hello.c` builds a program in about 0.1 s.
  - `tcc -run hello.c` runs a file without writing a binary.
  - A C file that starts with `#!/usr/bin/tcc -run` runs as a script.

  Examples are in `/usr/share/tcc-tests/`. Programs are linked dynamically
  only (`-static` fails).
- **Startup sound and volume** ([#292](https://github.com/redox-rpi/redox-rpi/issues/292),
  [#336](https://github.com/redox-rpi/redox-rpi/issues/336)). The Pi 3B+
  plays a short chime from the headphone jack at boot. It is our own,
  generated at runtime, and does not delay the boot. `off` in
  `/etc/startup-sound` turns it off. `volume` prints the volume, and
  `volume 70`, `+10`, `-10` and `mute` change it; the setting is kept
  across reboots. `reboot` and the new `poweroff` fade the output out, so
  the click at reboot and power-off is gone.
- **Network:**
  - The name server and local domain come from DHCP, with a timeout and
    retries ([#290](https://github.com/redox-rpi/redox-rpi/issues/290)):
    `fritz.box` and short names work. An unknown name now fails at once
    (`EAI_NONAME`, PR #381).
  - TCP close sends FIN (#184, PR #364).
  - `ifconfig` shows the adapter's MAC address and the netmask as
    `255.255.255.0` ([#171](https://github.com/redox-rpi/redox-rpi/issues/171)).
  - `nc` prints errors to stderr and exits with 1 (#407).
  - The Pi 3B+'s LAN7800 filters multicast in hardware, which wakes the
    system half as often when idle (#216).
- **curl** is in the Pi 3B+ images (not the Zero 2 W, no room), and the
  manifest lists what is installed (#365).
- **Fixes:**
  - The Pi 3B+ no longer hangs silently on an external abort (#311).
  - The USB driver no longer stalls long downloads (#151's download stall,
    PRs #344, #373).
  - `inputd` no longer panics after SIGSTOP/SIGCONT (#345).
  - A failing tool no longer prints a Rust backtrace (#291).

## Not in this candidate

These are on `main` as experiments but not in the release options. Build
them with `scripts/build-image.sh --experiment <name>`:
- C with cproc and QBE (`cproc-qbe`, #331, #384);
- relibc fixes still being tested: `scanf-pipe` (#359), `sig-pipe`
  (#379), `sigcont-restart` (#388);
- first-boot setup (`welcome`), SSH (`sshd`), IPv6 (`ipv6`), our package
  repository (`pkg-repo`).

The SD card still boots through U-Boot as in v0.4.0. Cards without U-Boot
(#324) wait for the maintainer's test of the direct cards.

## Known issues

**Desktop (beta):**
- Sopwith's window is cut off on small screens (656x416 without a
  monitor).
- Sopwith has no sound yet ([#335](https://github.com/redox-rpi/redox-rpi/issues/335)).
- One screen resolution, the firmware's mode at power-on; no HDMI hotplug.
- Orbital cannot be stopped once started; its memory comes back only with
  a reboot.
- Dragging a window costs about 90 % of a core (software compositing).
- The Zero 2 W **network-boot** image has no desktop (it does not fit in
  128 MiB). The SD card has the desktop on both boards.

**System:**
- **Network lost minutes after boot ([#92](https://github.com/redox-rpi/redox-rpi/issues/92))**
  and **login without network ([#217](https://github.com/redox-rpi/redox-rpi/issues/217))**:
  rare. PRs #344 and #373 remove the stall mechanisms found so far.
  *(Rate from the nightly network records of #369: to be filled in.)*
- First-boot setup is not in the image: the card logs in as `root` with
  password `password`, or as `user` without a password. Change the
  password on a network you do not trust.
- **Ctrl-C can be lost while a program starts**
  ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)).
- **A program whose last thread ends with `pthread_exit` is reported as
  killed** ([#108](https://github.com/redox-rpi/redox-rpi/issues/108)).
- **Signals sent to a single thread can get stuck**
  ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)).
- Text pasted very fast into the serial console can lose a character
  ([#28](https://github.com/redox-rpi/redox-rpi/issues/28)).
- curl prints `TODO: setsockopt(...)` lines for each connection (relibc).
  wget is not in the image because it corrupts HTTP downloads (#365).
- The Zero 2 W image has no curl; run `pkg install curl` there.
- Audio is a beta: about 11 bits, one fixed format (44.1 kHz).
- A Pi without a heatsink reaches the firmware's soft temperature limit
  (about 60 °C) under full load. The console logs a warning, and the
  clock stayed at 1400 MHz in the test.
- No Wi-Fi, Bluetooth or USB storage. Many prebuilt programs are not in
  the image ([#40](https://github.com/redox-rpi/redox-rpi/issues/40)).

## Install

1. Download `redox-rpi-v0.5.0-rc1.img.xz` from
   `http://homenodellm:8080/sdcard/` (test network) and check it against
   its `.sha256`. Or use SwiftFlash: `sudo swiftflash redox:`, family
   `redox-rpi`, version `v0.5.0-rc1`.
2. Write it to a microSD card of at least 2 GB:
   `xz -dc redox-rpi-v0.5.0-rc1.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync`.
   This erases everything on the card.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on. For sound, connect headphones to
   the 3.5 mm jack (Pi 3B+).
4. Log in as `root` with password `password`, or as `user` without a
   password. `desktop` starts the desktop (beta).
