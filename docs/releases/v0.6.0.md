**Status: experimental (alpha). Boots on the Pi 3B+ and Zero 2 W, not for
daily use.**

Redox OS on the Raspberry Pi 3 Model B+ and Zero 2 W
([checklist](v0.6.0-checklist.md), milestone
[v0.6.0](https://github.com/redox-rpi/redox-rpi/milestone/9)). v0.5.0 put
a game, a C compiler and a startup sound on the Pi; v0.6.0 makes the SD
card start without U-Boot and run from RAM, lets `poweroff` really switch
the Pi off, plays sound over HDMI, and fixes USB after a reboot, signals,
TCP and the kernel's TLB handling.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.5.0

- **The SD card starts without U-Boot** ([#324](https://github.com/redox-rpi/redox-rpi/issues/324),
  PRs #421, #515). The Pi firmware starts Redox directly from the card's
  FAT partition. One card serves both boards. The whole system runs from
  RAM, as with network boot: the root filesystem is at most 256 MiB, and
  changes to it are gone after a reboot. Files to keep go on the data
  partition. The banner says `(direct, …)`.
- **Sound over HDMI** ([#423](https://github.com/redox-rpi/redox-rpi/issues/423),
  PRs #432, #613), on the Pi 3B+ and the Zero 2 W, which has no jack.
  The startup sound, `tone` and Sopwith play on the monitor's speakers.
  The 3.5 mm jack is silent in this release (see Known issues).
- **USB works after a warm reboot** on the Pi 3B+
  ([#576](https://github.com/redox-rpi/redox-rpi/issues/576), PR #603):
  before, about one reboot in three came up without USB and network; now
  100 of 100 reboots had network (Pi test 570).
- **`poweroff` switches the Pi off** (PR #526)
  ([#418](https://github.com/redox-rpi/redox-rpi/issues/418)). The system
  halts through the watchdog; the Pi then draws no measurable power (Pi
  test 469: 0.00 W). Unplug and plug in to start again.
- **Programs and signals:**
  - A pending signal is delivered before and after a blocking call (#387, PR #399).
  - A killed program still cancels its requests to a driver (#401, PR #403).
  - A program whose last thread ends with `pthread_exit` exits with
    status 0 instead of being reported as killed
    ([#108](https://github.com/redox-rpi/redox-rpi/issues/108), PR #174).
- **Network:**
  - A TCP read while the connection is still being made waits instead of
    returning end of file (#404, PR #406).
  - A read after the other side resets a TCP connection returns the data
    already received first (#141, PR #454).
  - `ifconfig` shows the MAC address in every image, also the Zero 2 W's
    and the network-boot ones (#444, PR #446).
- **Kernel:**
  - No stale TLB entries on the Cortex-A72 (#332, PR #356), the base for the Pi 4 and 400.
  - The context switch handles TLB shootdowns while it waits for a lock (#207, PR #209).
  - RedoxFS frees the last partial record of a removed file; a futex race is fixed (#197, PR #402).
- **Network boot:** U-Boot's TCP downloads are more reliable on the GENET
  Ethernet, with retries and diagnostics (#394, PR #465). This concerns
  network boot and the U-Boot card, not the direct card.
- **Build:** the same build ID means the same image, whatever the build
  clone built before (#447, PR #448); the binary packages' dependencies
  are fetched (#519).

## Not in this release

These are on `main` as experiments but not in the release options. Build
them with `scripts/build-image.sh --experiment <name>`:
- Ctrl-C while a program starts (`pty-sigint`, #55, PR #121);
- C with cproc and QBE (`cproc-qbe`, #327);
- the gamepad test window (`gamepad-test`, #320);
- diagnostics: `irq-stats` (#564), `netdiag` (#566), `serial-rx2` (#28),
  `boot-no-errors` (#556);
- first-boot setup (`welcome`), SSH (`sshd`), IPv6 (`ipv6`), our package
  repository (`pkg-repo`).

The U-Boot card of v0.5.0 is still built as a fallback but not published.
The Pi 400 work (QEMU `raspi4b`, PCIe and the keyboard behind the VL805
hub, #310, #385) is an experiment and not in this release.

## Known issues

Carried over from v0.5.0 unless fixed above.

**Direct card:**
- The system runs from RAM: on the Zero 2 W (512 MB) the 256 MiB
  initramfs leaves less memory for programs. Row 449 records `free` after
  the desktop and Sopwith.
- Changes to the root filesystem are lost at reboot (passwords, files in
  `/home`).

**Desktop (beta):**
- Sopwith's window is cut off on small screens (656x416 without a monitor).
- One screen resolution, the firmware's mode at power-on; no HDMI hotplug.
- Orbital cannot be stopped once started; its memory comes back only with a reboot.
- Dragging a window costs about 90 % of a core (software compositing).
- The Zero 2 W **network-boot** image has no desktop.

**System:**
- **Network lost minutes after boot ([#92](https://github.com/redox-rpi/redox-rpi/issues/92))**
  and **login without network ([#217](https://github.com/redox-rpi/redox-rpi/issues/217))**: rare.
- First-boot setup is not in the image: log in as `root` with password
  `password`, or as `user` without a password.
- **Ctrl-C can be lost while a program starts** ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)).
- **Signals sent to a single thread can get stuck** ([#4](https://github.com/redox-rpi/redox-rpi/issues/4))
  *(fixed if PR #142 is merged)*.
- Text pasted very fast into the serial console can lose a character ([#28](https://github.com/redox-rpi/redox-rpi/issues/28)).
- curl prints `TODO: setsockopt(...)` lines; the Zero 2 W image has no curl.
- **Sound only over HDMI; the 3.5 mm jack of the Pi 3B+ is silent.**
  The HDMI driver replaces the jack driver, and you cannot choose between
  them yet. Choosing HDMI or the jack is planned for v0.7.0
  ([#617](https://github.com/redox-rpi/redox-rpi/issues/617)). A monitor
  without speakers or a DVI screen gives no sound.
- Audio is a beta: one fixed format (44.1 kHz, stereo).
- **Without an Ethernet cable or adapter, the DHCP client keeps writing
  lines to the console.** From v0.7.0 it starts only on a connected
  adapter ([#560](https://github.com/redox-rpi/redox-rpi/issues/560), PR #614).
- **Memory grows by about 0.3 MB per TCP connection** to a server on the
  Pi and does not come back until a reboot
  ([#610](https://github.com/redox-rpi/redox-rpi/issues/610)); seen with
  1000 connections to the test shell, which is not in the release image.
- Only one USB keyboard, mouse or gamepad works at a time ([#450](https://github.com/redox-rpi/redox-rpi/issues/450)).
- No Wi-Fi, Bluetooth or USB storage. Many prebuilt programs are not in
  the image ([#40](https://github.com/redox-rpi/redox-rpi/issues/40)).

## Install

1. Download `redox-rpi-v0.6.0-pi3bplus.img.xz` from this release and check
   it against `SHA256SUMS`. The same card works in the Pi 3 Model B+ and
   the Zero 2 W. With SwiftFlash on the test network:
   `sudo swiftflash redox:redox-rpi` and pick version `v0.6.0`.
2. Write it to a microSD card of at least 2 GB. Use Raspberry Pi Imager
   ("Use custom"), balenaEtcher or SwiftFlash, or on Linux and macOS:

   ```sh
   xz -dc redox-rpi-v0.6.0-pi3bplus.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on. The Pi starts Redox directly,
   without a boot menu. For sound, use a monitor or TV with speakers on
   HDMI; the jack is silent (#617).
4. Log in as `root` with password `password`, or as `user` without a
   password. `desktop` starts the desktop (beta). `poweroff` switches the
   Pi off.

The [getting started guide](https://github.com/redox-rpi/redox-rpi/blob/main/docs/getting-started.md)
explains each step.

## Built from

Build `v0.6.0-dev-135-g0897391f+x6a9f` from `main` at
[0897391f](https://github.com/redox-rpi/redox-rpi/commit/0897391f), the
commit of v0.6.0-rc3, with the experiments `timesync`, `rpi-fb`, `orbital`,
`orbital-apps`, `cosmic-apps-source`, `desktop`, `tcc`, `usb-port-power`
and `hdmi-audio`. Redox upstream at the commits in
[config/upstream.lock](https://github.com/redox-rpi/redox-rpi/blob/v0.6.0/config/upstream.lock),
with this repository's patches. SHA-256 of
`redox-rpi-v0.6.0-pi3bplus.img.xz`: `7cafb724fb88c907ebaa2fc73b3a94b4fdfe6a67ff13d62896dc58bceec61a10`.
The image's `/etc/redox-rpi-manifest` lists every patch and package with
its hash.

The release image was built again from rc3's commit with the same options
and only the release name changed. Its manifest lists the same patches and
the same hash for every package as rc3's, except `tcc`, which is built
from a local source tree and gets a new hash with each build. The release
image has no `devshd` (REQ-REL-1) and the same size as rc3's (REQ-REL-5).

The candidates passed:
- rc2 and rc3, automated Pi tests on a Pi 3B+: 100 of 100 reboots with
  network (#576), 1000 program starts, five reboots, `poweroff`, serial
  input, 100 MiB downloads with curl and nc, DNS, tcc, desktop and
  Sopwith; HDMI sound (rate, info frame, no underflow); the release
  variant without a remote shell and with no open port;
- the maintainer's tests from the SD card on a Pi 3B+ and a Zero 2 W:
  login, network and clock, desktop, Sopwith with sound over HDMI;
- QEMU: the regression set (0 of 300 starts failed), the desktop check
  and the HDMI sound check.
