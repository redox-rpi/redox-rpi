How the candidates for v0.4.0 are built and tested
([release-process.md](../release-process.md)). Tracking issue:

## Candidate rc1

The user asked for a v0.4 candidate on 2026-11-07. rc1 is current `main`
after the last `merge-next` set was merged (#204, #163, #137, #81, all
2026-11-07 ~21:19 UTC):

- commit [4804fe63](https://github.com/redox-rpi/redox-rpi/commit/4804fe63750cb6d438f31c829aba5b62fb0e97dd)
  ("netstack uses every network adapter", #81); #252 (docs only, after it)
  does not change the image;
- options `--release v0.4.0-rc1 --experiment timesync`, as for v0.3.0;
- built in `~/redox-rpi-rel`, branch `release-v0.4.0`, with
  `logs/v040-rc1-build.sh`: SD card, then netboot and Zero 2 W;
- SD image published with `scripts/publish-sdcard.sh --family redox-rpi
  --version v0.4.0-rc1` ([ci.md](../topics/ci.md#image-server)):
  `http://homenodellm:8080/sdcard/redox-rpi-v0.4.0-rc1.img.xz`
  (SwiftFlash: family `redox-rpi`, version `v0.4.0-rc1`);
- netboot `keep/v0.4.0-rc1-netboot.img`, Zero 2 W `keep/v0.4.0-rc1-zero2w.img`.

Build ID, checksum and test results: [rc1 build](#rc1-build) below.
