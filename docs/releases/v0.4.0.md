**Status: experimental (alpha). Boots on the Pi 3B+ and Zero 2 W, not for
daily use.**

Redox OS on the Raspberry Pi 3 Model B+ and Zero 2 W
([checklist](v0.4.0-checklist.md),
[#253](https://github.com/redox-rpi/redox-rpi/issues/253)). v0.3.0 made the
system dependable; v0.4.0 makes the SD card fast for small writes, gives the
Pi sound from its headphone jack (beta), and lets the network use every
adapter at once.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.3.0

- **Optional desktop (beta)** ([PR #255](https://github.com/redox-rpi/redox-rpi/pull/255)).
  The image now contains Redox's desktop, Orbital, with the COSMIC text
  editor and file manager and the orbterm terminal. It does not start at
  boot: the Pi boots to the text console as before, and after each login
  the message of the day says: "Type `desktop` to start the graphical
  desktop (beta); as user: `sudo desktop`." As root, `desktop`
  (or `sudo desktop`) shows a short beta warning and asks
  `Start the desktop? [y/N]`; only `y` starts it. Log in as `user` with an
  empty password (press Enter). Super+F2 goes back to the text console,
  Super+F3 (or `desktop` again) to the desktop. `desktop --yes` starts it
  without asking, for scripts. The desktop uses the firmware's display
  (`rpi-fbd`); the image is about 42 MiB as `.img.xz` instead of 21 MiB.
- **Sound from the headphone jack (beta)**
  ([#250](https://github.com/redox-rpi/redox-rpi/issues/250)). A new
  driver, `bcm2835-pwmaudiod`, plays sound through the Pi 3B+'s 3.5 mm jack
  with DMA, and the Redox sound service `audiod` runs again. `tone` makes
  test sound: `tone -s 3 > /scheme/audio`. Limits of the beta: about
  11 bits, one fixed format (44.1 kHz, 16-bit stereo), the output keeps
  running after the sound ends, a faint hiss when idle. The listening test
  passed (#280).
- **Small writes to the SD card are fast**
  ([#16](https://github.com/redox-rpi/redox-rpi/issues/16)). The
  filesystem collects small writes and writes them together: copying 1 MiB
  in 4 KiB blocks takes 0.5 s instead of 12.7 s. Collected data is written
  at the latest 2 s after it came.
- **Every network adapter at once**
  ([#53](https://github.com/redox-rpi/redox-rpi/issues/53)). The network
  stack uses the onboard Ethernet and USB Ethernet adapters together, and
  the DHCP client gets an address for each.
- **Programs keep their registers across signals**
  ([#127](https://github.com/redox-rpi/redox-rpi/issues/127)). Returning
  from a signal handler no longer overwrites the x18 register.
- **Long downloads no longer stall**
  ([#157](https://github.com/redox-rpi/redox-rpi/issues/157)). The kernel's
  scheduler can no longer lose a thread that is ready to run, and a write
  into a pipe waits until all its bytes are in, so `dd` into a pipe keeps
  its data ([#158](https://github.com/redox-rpi/redox-rpi/issues/158)).
- **IPv4 multicast** ([#27](https://github.com/redox-rpi/redox-rpi/issues/27)),
  also through the Pi 3B+'s LAN7800 adapter, for mDNS and similar
  protocols.
- **USB mice and tablets** are seen by the USB driver and reported as input
  events ([#48](https://github.com/redox-rpi/redox-rpi/issues/48)), ready for
  a desktop.
- **Fixes:**
  - The network stack frees a closed TCP connection
    ([#88](https://github.com/redox-rpi/redox-rpi/issues/88)).
  - The bootloader skips a damaged RedoxFS partition instead of stopping
    ([#232](https://github.com/redox-rpi/redox-rpi/issues/232)).
  - The dynamic loader reads a program from disk only once
    ([#240](https://github.com/redox-rpi/redox-rpi/issues/240)).
  - `clock_settime` and `settimeofday` work, so `timesync -s` can set the
    clock by hand ([#51](https://github.com/redox-rpi/redox-rpi/issues/51)).
- **The CPU clock can be set at boot** in `/etc/rpi-firmware/governor`
  (`ondemand`, `performance`, `powersave` or a fixed rate,
  [#23](https://github.com/redox-rpi/redox-rpi/issues/23)).
- **`socdump`** prints the Pi's clock, PLL and GPIO registers, read-only
  ([#224](https://github.com/redox-rpi/redox-rpi/issues/224)).

All issues of this release:
[milestone v0.4.0](https://github.com/redox-rpi/redox-rpi/milestone/3?closed=1).

## Not in this release

These are experiments: they are on `main` but not in the release image.
Build them with `scripts/build-image.sh --experiment <name>`:

- SSH server (`sshd`, [#45](https://github.com/redox-rpi/redox-rpi/issues/45)),
  IPv6 with SLAAC (`ipv6`), ping replies (`icmp-echo`);
- time zones with summer time (`timezone`,
  [#46](https://github.com/redox-rpi/redox-rpi/issues/46));
- our package repository, packages that survive a reset (`pkg-repo`,
  `pkg-persist`, `pkg-hold`, [#44](https://github.com/redox-rpi/redox-rpi/issues/44));
- first-boot welcome app (`welcome`), faster boot (`boot-time`,
  `dwc2d-boottime`, [#47](https://github.com/redox-rpi/redox-rpi/issues/47));
- power saving (`eth-speed`, `clock-states`), USB controller restart
  (`dwc2d-restart`, [#151](https://github.com/redox-rpi/redox-rpi/issues/151));
- booting straight from the Pi firmware without U-Boot
  ([#15](https://github.com/redox-rpi/redox-rpi/issues/15)).

## Known issues

**Desktop (beta):**

- **Saving in the COSMIC text editor does not work**: the save dialog
  takes up to 30 s or does not appear
  ([#33](https://github.com/redox-rpi/redox-rpi/issues/33)). v0.4.1
  replaces the editor with a game.
- The text editor can take up to 40 s to open its first window (about 7 s
  in the maintainer's test) and costs half a core or more while typing (it redraws its whole window per key).
- Dragging a window costs about 90 % of a core (software compositing).
- No web browser and no COSMIC terminal; orbterm (Super+T) is the terminal.
- One screen resolution, the firmware's mode at power-on; no HDMI hotplug.
- Orbital cannot be stopped once started; its memory (40 to 80 MB) comes
  back only with a reboot.
- The Zero 2 W **network-boot** image has no desktop: it does not fit its
  128 MiB. The SD card has the desktop on both boards.

**System:**

- **Audio is a beta:** see the limits above. A small click in the
  headphones at power-off and at reboot.
- **Ctrl-C can be lost while a program starts**
  ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)).
- **A program whose last thread ends with `pthread_exit` is reported as
  killed** ([#108](https://github.com/redox-rpi/redox-rpi/issues/108)): its
  exit status is SIGKILL instead of 0 (relibc test `pthread/exit`). The fix
  is the experiment `self-exit-status`, not in the image.
- **Signals sent to a single thread can get stuck**
  ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)).
- **The Pi can hang during a long write to the SD card while it
  downloads** ([#151](https://github.com/redox-rpi/redox-rpi/issues/151));
  QEMU doesn't show it.
- Text pasted very fast into the serial console can still lose a character
  now and then ([#28](https://github.com/redox-rpi/redox-rpi/issues/28);
  19 of 20 lines in tests 285 and 292). Typing and the network shell are not
  affected.
- No HTTP client in the image (`curl`, `wget`, `netget`); `nc` works.
- **DNS:** short names fail, and `fritz.box` hangs with no timeout; the
  DNS server from DHCP is ignored
  ([#290](https://github.com/redox-rpi/redox-rpi/issues/290)).
- `ifconfig` shows the MAC address `00:00:00:00:00:00` on every adapter
  ([#171](https://github.com/redox-rpi/redox-rpi/issues/171)), and there is
  no `ip` command.
- A failing tool prints a Rust stack backtrace of `<unknown>` frames on
  the console ([#291](https://github.com/redox-rpi/redox-rpi/issues/291)).
- No Wi-Fi, Bluetooth, USB storage or `poweroff`.
- Many prebuilt programs (bash, nano, vim, curl, …) are not in the image
  ([#40](https://github.com/redox-rpi/redox-rpi/issues/40)).

## Install

1. Download `redox-rpi-v0.4.0-pi3bplus.img.xz` and check it against
   `SHA256SUMS`. With SwiftFlash on the test network:
   `sudo swiftflash redox:` and pick family `redox-rpi`, version `v0.4.0`.
2. Write it to a microSD card of at least 2 GB. Use Raspberry Pi Imager
   ("Use custom"), balenaEtcher or SwiftFlash, or on Linux and macOS:

   ```sh
   xz -dc redox-rpi-v0.4.0-pi3bplus.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on. A boot menu shows for 3 seconds
   and then boots the card; its network entries are for our test network.
   For sound, headphones in the 3.5 mm jack (Pi 3B+).
4. Log in as `root` with password `password`, or as `user` without a
   password. `desktop` starts the desktop (beta).

The [getting started guide](https://github.com/redox-rpi/redox-rpi/blob/v0.4.0/docs/getting-started.md)
explains each step.

## Built from

Build `v0.4.0-dev-809-g5723a434+x4aaf` from `main` at
[5723a434](https://github.com/redox-rpi/redox-rpi/commit/5723a434), the
commit of v0.4.0-rc2, with the experiments `timesync`, `rpi-fb`, `orbital`,
`orbital-apps`, `cosmic-apps-source` and `desktop`. Redox upstream at the
commits in
[config/upstream.lock](https://github.com/redox-rpi/redox-rpi/blob/v0.4.0/config/upstream.lock),
with this repository's patches. SHA-256 of
`redox-rpi-v0.4.0-pi3bplus.img.xz`:
`ab828e2265cb7d3c89d9e268f4107bb2ee3613ea1d37dd3c64dbebab566278f4`. The image's
`/etc/redox-rpi-manifest` lists every patch and package with its hash.

The release image was built again from rc2's commit with the same options
and only the release name changed; kernel, `libc.so` and every package but
one have the same hash as in rc2. The exception is `pkgutils` (the `pkg`
tool): its recipe follows upstream git and was built again from a newer
state. rc2 passed on a Pi 3B+ (1000 program starts, five
reboots, audio, SD card writes, desktop start) and with the maintainer on a
Pi 3B+ and a Zero 2 W from the SD card (HDMI, keyboard and mouse, desktop,
network, clock, no remote shell), and in QEMU (six checks, 0 of 300 starts
failed, audio).
