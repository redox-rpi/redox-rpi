**Status: experimental (alpha). Boots on the Pi 3B+ and Zero 2 W, not for
daily use.**

Redox OS on the Raspberry Pi 3 Model B+ and Zero 2 W
([checklist](v0.7.0-checklist.md), milestone
[v0.7.0](https://github.com/redox-rpi/redox-rpi/milestone/10)). v0.6.0
started the SD card without U-Boot and played sound over HDMI; v0.7.0
shows local time, makes the network start only on a connected adapter
from one config file, ends a program that runs out of memory instead of
the whole system, and makes downloads on the Pi 3B+ steadier.

This is an **unofficial, AI-assisted fork** and not part of the Redox OS
project. Please report problems here, not to Redox.

## New since v0.6.0

- **Local time** ([#46](https://github.com/redox-rpi/redox-rpi/issues/46),
  PR #709). Every image is set to Europe/Berlin with summer time: `date`
  shows CET or CEST, `date -u` shows UTC. `env TZ=UTC date` gives UTC for
  one command. To change the zone, see [time.md](../time.md#time-zones).
- **A write to a memory-mapped file no longer stops the system**
  ([#678](https://github.com/redox-rpi/redox-rpi/issues/678), PR #702).
  A write to a private, writable mapping of a file on a scheme such as
  `/tmp` panicked the kernel. Now the kernel keeps running; the program
  that writes still hangs (see known issues).
- **Out of memory ends the program, not the system**
  ([#644](https://github.com/redox-rpi/redox-rpi/issues/644), PR #662).
  A program that runs out of memory is killed with
  `OUT OF MEMORY: killing PID …` on the console; before, the kernel
  panicked. This mattered most on the Zero 2 W (512 MB).
- **USB after a warm reboot in every image** ([#576](https://github.com/redox-rpi/redox-rpi/issues/576),
  PR #729). The root port power cycle that v0.6.0 had as a release option
  is now a default patch, so network-boot and test images get USB and
  network back after `reboot` as well.
- **Network:**
  - DHCP starts only on an adapter with a cable plugged in, so a Zero 2 W
    without an Ethernet adapter no longer fills the console with DHCP
    lines ([#560](https://github.com/redox-rpi/redox-rpi/issues/560),
    PR #614). The USB driver reports ready without waiting for the link,
    so the boot does not wait for it either (#536).
  - One network config file, `/etc/net/config.toml`, says which
    interfaces use DHCP ([#622](https://github.com/redox-rpi/redox-rpi/issues/622),
    PR #628, step 1). See [network-config.md](../network-config.md).
  - Steadier downloads on the Pi 3B+: the LAN7800 receive path no longer
    overruns its FIFO and uses flow control (#661, PR #665).
  - A busy connection keeps working while the Pi asks again for an
    address that is about to expire from the ARP table (#140, PR #463).
  - The Pi answers ping from other hosts (#177), and the USB network
    driver wakes less often when idle (#211) (PR #694).
  - `dhcpd` reads the board from the devicetree, so the `boards` key in
    `/etc/net/config.toml` tells the Pi 3B+ and the Zero 2 W apart
    ([#653](https://github.com/redox-rpi/redox-rpi/issues/653), PR #659).
  - A fixed address: a section with `ipv4 = "static"` in
    `/etc/net/config.toml` sets the address, and optionally the router
    and name server, without DHCP (#622, PR #732). See
    [network-config.md](../network-config.md).
  - `getsockname` on a socket that is not bound or connected returns
    `0.0.0.0:0` instead of ending the program; the `ssh` client needed
    this (#712, PR #739).
- **System:**
  - `randd` seeds the random number generator from the BCM2835 hardware
    RNG ([#618](https://github.com/redox-rpi/redox-rpi/issues/618),
    PR #620).
  - The firmware picture fills the screen: `disable_overscan=1`, 1920x1080
    instead of 1824x984 (#347, PR #348).
  - `audiotop` shows the audio driver's counters live (#565, PR #567).
  - Sopwith quits on SIGTERM, and `kill -KILL` ends it at once (#405,
    PR #460).
  - Three relibc signal fixes move from experiments into every image (#690, PR #695): a child made by `fork()` gets its
    signals again (#205), a signal without a handler restarts the call it
    interrupted (#386), and a pending signal is delivered before and after
    a blocking call (#387).
  - A failing tool no longer prints a Rust backtrace (#291), and a
    driver that restarts can register its scheme again (#117) (PR #697).
  - `gmtime` returns UTC, and `tzset` names the summer time (CEST), so C
    programs show the same time as `date`
    ([#744](https://github.com/redox-rpi/redox-rpi/issues/744), PR #748).
  - Statically linked programs that use thread-local storage no longer
    crash on aarch64 (#375, PR #747).
- **Desktop:** the login window keeps its picture only at window size,
  about 6 MB less memory at 1920x1080, which matters on the Zero 2 W
  (#616, PR #756).
- **Packages:** `mdnsd` is in our package repository (`pkg install
  mdnsd`), not in the image (#37, PR #558).

### New experiments

On `main` but not in the release image; build them with
`scripts/build-image.sh --experiment <name>`. They are for the Pi 4 and
Pi 400, which are not supported boards in this release:
- **3D graphics core (V3D):** `v3d-power` powers the V3D core through the
  firmware, `v3dd` is its daemon (#598, PR #716), `v3d-ioctl` lets relibc
  pass the V3D and syncobj ioctls on (#669, PR #717), and `mesa-v3d`
  builds Mesa's v3d driver with `gles-probe`, an OpenGL ES 2.0 test
  (#669, PR #718). They need experiment `pi400`.
- **Pi 400:** all its RAM (`pi400-mem`, #299, PR #580), the German
  layout with the ISO keys (`keyboard-de`, #36, PR #581), HDMI sound on
  the BCM2711's ports (`hdmi-audio` with `pi400`, #543, PR #548), vc4d
  as display driver with vblank (PR #689), the V3D rendering into vc4d's
  buffers (`v3d-prime`, #670, PR #722), and SDL2 with OpenGL ES on the
  V3D (`sdl2-gles`, #669, PR #720), and Orbital compositing on the GPU
  (`orbital-gl`, #670, PR #733).
- **Diagnostics:** `driver-status` (#571), `irq-stats` (#564), `netdiag`
  (#566), and `mmapstop` with a test fix for the mmap kernel panics
  (#678, PR #701).

## Not in this release

On `main` as experiments, not in the release options. Build them with
`scripts/build-image.sh --experiment <name>`:
- the new experiments above;
- keeping installed packages across reboots on a RAM root (`pkg-persist`);
- first-boot setup (`welcome`), SSH (`sshd`), IPv6 (`ipv6`), our package
  repository (`pkg-repo`).

## Known issues

Carried over from v0.6.0 unless fixed above.

**Direct card:**
- The system runs from RAM: on the Zero 2 W the 256 MiB initramfs leaves
  less memory for programs.
- Changes to the root filesystem are lost at reboot (passwords, files in
  `/home`, the time zone link).

**Desktop (beta):**
- Sopwith's window is cut off on small screens (656x416 without a monitor).
- One screen resolution, the firmware's mode at power-on; no HDMI hotplug.
- Orbital cannot be stopped once started; its memory comes back only with a reboot.
- On the Zero 2 W the login window and a terminal still take much of the
  free memory ([#616](https://github.com/redox-rpi/redox-rpi/issues/616)).
- The Zero 2 W **network-boot** image has no desktop.

**System:**
- **Sound only over HDMI; the 3.5 mm jack of the Pi 3B+ is silent**
  ([#617](https://github.com/redox-rpi/redox-rpi/issues/617)). Choosing
  the output is not in this release.
- **Network lost minutes after boot ([#92](https://github.com/redox-rpi/redox-rpi/issues/92))**
  and **login without network ([#217](https://github.com/redox-rpi/redox-rpi/issues/217))**: rare.
- First-boot setup is not in the image: log in as `root` with password
  `password`, or as `user` without a password.
- **Ctrl-C can be lost while a program starts** ([#55](https://github.com/redox-rpi/redox-rpi/issues/55)).
- On the serial console, Ctrl-C pressed right after Enter stops the
  program only when it ends by itself; a second later it works
  ([#86](https://github.com/redox-rpi/redox-rpi/issues/86)).
- **Signals sent to a single thread can get stuck** ([#4](https://github.com/redox-rpi/redox-rpi/issues/4)).
- Text pasted very fast into the serial console can lose a character ([#28](https://github.com/redox-rpi/redox-rpi/issues/28)).
- curl prints `TODO: setsockopt(...)` lines; the Zero 2 W image has no curl.
- Audio is a beta: one fixed format (44.1 kHz, stereo).
- **Memory grows by about 0.3 MB per TCP connection** to a server on the
  Pi ([#610](https://github.com/redox-rpi/redox-rpi/issues/610)).
- Only one USB keyboard, mouse or gamepad works at a time ([#450](https://github.com/redox-rpi/redox-rpi/issues/450)).
- No Wi-Fi, Bluetooth or USB storage. Many prebuilt programs are not in
  the image ([#40](https://github.com/redox-rpi/redox-rpi/issues/40)).

**Kernel and programs:**
- A program that writes to a private, writable mapping of a file in
  `/tmp` hangs; `kill -KILL` ends it
  ([#678](https://github.com/redox-rpi/redox-rpi/issues/678), fix in
  PR #703). *(drop this line if #703 is merged)*
- With almost no memory left, the kernel can still stop in a few places
  (grant mapping, kernel heap) ([#663](https://github.com/redox-rpi/redox-rpi/issues/663)).
  A program that uses up the memory itself is ended instead (see above).
- A `fork()` that fails for lack of memory leaves a half-made child
  process behind ([#707](https://github.com/redox-rpi/redox-rpi/issues/707)).
- A file mapped with `mmap` right after a `write()` can show the old data
  ([#704](https://github.com/redox-rpi/redox-rpi/issues/704)).
- `kill` (SIGTERM) sometimes does not end a program that waits on a
  driver, for example the audio driver; `kill -KILL` does
  ([#660](https://github.com/redox-rpi/redox-rpi/issues/660)).
- Reading a pipe with `fscanf` can lose input
  ([#338](https://github.com/redox-rpi/redox-rpi/issues/338)).
- `sleep` can, rarely, never return on the Pi 3B+
  ([#372](https://github.com/redox-rpi/redox-rpi/issues/372)).

## Install

1. Download `redox-rpi-v0.7.0-pi3bplus.img.xz` from this release and check
   it against `SHA256SUMS`. The same card works in the Pi 3 Model B+ and
   the Zero 2 W. With SwiftFlash on the test network:
   `sudo swiftflash redox:redox-rpi` and pick version `v0.7.0`.
2. Write it to a microSD card of at least 2 GB. Use Raspberry Pi Imager
   ("Use custom"), balenaEtcher or SwiftFlash, or on Linux and macOS:

   ```sh
   xz -dc redox-rpi-v0.7.0-pi3bplus.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync
   ```

   Everything on the card is erased.
3. Put the card into a Pi 3 Model B+ or Zero 2 W. Connect HDMI, a USB
   keyboard and Ethernet, then power on. The Pi starts Redox directly,
   without a boot menu. For sound, use a monitor or TV with speakers on
   HDMI.
4. Log in as `root` with password `password`, or as `user` without a
   password. `desktop` starts the desktop (beta). `poweroff` halts the
   Pi; the red LED stays on until you unplug it.

The [getting started guide](https://github.com/redox-rpi/redox-rpi/blob/main/docs/getting-started.md)
explains each step.
