# v0.3.0 candidate checklist (draft)

How the next candidate for v0.3.0 is built and tested
([release-process.md](../release-process.md)). v0.3.0-rc1 was the SD card
session's sdhost test image, so the next candidate is **v0.3.0-rc2**.

coordinator decides with the user.

## Build options

Built in `~/redox-rpi-rel` from one commit of `main`, without
`--allow-dirty`. sdhost, cpu-clock, pi-clean-boot and (if #5 passes)
dwc2-interrupts are default patches by then, so only the remaining
experiments are named:

```bash
OPTS="--release v0.3.0-rc2 --experiment timesync --experiment rtl8152"
scripts/build-image.sh --sdcard $OPTS    # release image (SD card, Pi 3B+ and Zero 2 W)
scripts/build-image.sh $OPTS             # netboot, Pi 3B+, for the automated tests
scripts/build-image.sh --zero2w $OPTS    # netboot, Zero 2 W (128 MiB image)
```

Not in the release: `ldso-diagnostics` and devshd. The SD card config
(`config/raspi3bp-sdcard.toml`) has no devshd; the netboot images have it,
for `pi-test.py`.

Results go to `/srv/tftp/sdcard/` as `redox-rpi-v0.3.0-rc2.img.xz` with its
manifest and `SHA256SUMS`.

## Tests

| # | Test | Image | Needs the user |
|---|---|---|---|
| 1 | Boot over the network, `scripts/pi-test.py` standard checks, 1000 starts | netboot Pi 3B+ | no |
| 2 | CPU at 1400 MHz: boot log line, `/scheme/rpi-firmware/clocks`, no throttle warnings | netboot Pi 3B+ | no |
| 3 | Clean boot: no `pcid`, `audiod` in the serial log | netboot Pi 3B+ | no |
| 4 | Clock from NTP after boot | netboot Pi 3B+ | no |
| 5 | `reboot` 5 times | netboot Pi 3B+ | no |
| 6 | **SD card image** boots to the login prompt from the card, root on the card, `sd-stress.py` short run | SD card, Pi 3B+ | **yes**: write the card and put it in |
| 7 | **HDMI and USB keyboard**: login on HDMI, `Super` + `F1`/`F2` | SD card, Pi 3B+ | **yes**: screen and keyboard |
| 8 | **USB hotplug** (if #17 is in): keyboard plugged in after boot | SD card, Pi 3B+ | **yes**: plug the keyboard |
| 9 | **Zero 2 W**: same SD card boots, RTL8152 hub gets DHCP and NTP | SD card, Zero 2 W | **yes**: move the card, connect the hub |
| 10 | Release download: `curl` the `.img.xz` from homenodellm, `sha256sum -c` | — | no |

Tests 1 to 5 and 10 run without anyone. Tests 6 to 9 need the user and fit
into **one visit**, in this order: write the SD card, Pi 3B+ with HDMI and
keyboard (6, 7, 8), then move the card to the Zero 2 W (9). After the visit
the netboot card goes back into the Pi 3B+, so the nightly stable image
can boot again.
