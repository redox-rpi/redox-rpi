## Build options

Built in `~/redox-rpi-rel` from one commit of `main`, without
`--allow-dirty`. Once the four branches above are merged, only `timesync`
is still an experiment (it adds a package, no patches):

```bash
OPTS="--release v0.3.0-rc2 --experiment timesync"
scripts/build-image.sh --sdcard $OPTS    # release image (SD card, Pi 3B+ and Zero 2 W)
scripts/build-image.sh $OPTS             # netboot, Pi 3B+, for the automated tests
scripts/build-image.sh --zero2w $OPTS    # netboot, Zero 2 W (128 MiB image)
```

If a branch is not merged at build time, its experiments are named instead:
`--experiment rtl8152 --experiment dwc2-interrupts` (dwc2),
`--experiment serial-rx`, `--experiment sdhost-driver --experiment
sdhost-boot` (sdhost). `pi-clean-boot` and `ctx-leak-fix` only exist on
their branches until they merge.

Not in the release: `ldso-diagnostics` and devshd. The SD card config
(`config/raspi3bp-sdcard.toml`) has no devshd; the netboot images have it,
for `pi-test.py`.

Results go to `/srv/tftp/sdcard/` as `redox-rpi-v0.3.0-rc2.img.xz` with its
manifest and `SHA256SUMS`.

| # | Test | Image | Needs the user |
|---|---|---|---|
| 1 | Boot over the network, `scripts/pi-test.py` standard checks, 1000 starts | netboot Pi 3B+ | no |

| 9 | **Zero 2 W**: same SD card boots, RTL8152 hub gets DHCP and NTP | SD card, Zero 2 W | **yes**: move the card, connect the hub |
| 10 | Release download: `curl` the `.img.xz` from homenodellm, `sha256sum -c` | — | no |
| 11 | Serial input: `serial-input-test.sh` from the `serial-rx` experiment, fast input on the serial console | netboot Pi 3B+ | no |
| 12 | Nightly stable run of the rc2 commit passes (`scripts/update-stable.sh`) | netboot Pi 3B+ | no |

Tests 1 to 5 and 10 to 12 run without anyone. Tests 6 to 9 need the user and fit
into **one visit**, in this order: write the SD card, Pi 3B+ with HDMI and
keyboard (6, 7, 8), then move the card to the Zero 2 W (9). After the visit
the netboot card goes back into the Pi 3B+, so the nightly stable image
can boot again.
